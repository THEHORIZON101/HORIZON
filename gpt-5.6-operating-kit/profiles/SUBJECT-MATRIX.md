## Selection rule

Start with the cheapest/fastest configuration likely to pass. Move upward only when the task has ambiguity, multiple dependencies, consequential trade-offs, demanding polish, or failed verification.

## Do not stack every skill

Use one lead skill, the few support skills that add a distinct capability, and one or two verification skills. Excessive skill loading consumes context and can create conflicting workflows.
